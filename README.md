# Архітектура Проєкту: Clean & Hexagonal Architecture + Uber Fx

Цей проєкт побудований на принципах **Чистої (Clean)** та **Гексагональної (Hexagonal / Ports & Adapters)** архітектури з використанням Dependency Injection фреймворку **Uber Fx** та CLI-менеджера **Cobra**.

Головна мета архітектури — повна ізоляція бізнес-логіки системи від зовнішніх факторів: баз даних, черг повідомлень, веб-фреймворків та протоколів зв'язку.

---

## Структура папок та розподіл відповідальності

```text
.
├── cmd/
│   └── app.go                  # Точка входу. Ініціалізує Cobra CLI команди           
│
├── internal/
│   ├── app/                    # БУТСТРАП (Складання додатків за допомогою Uber Fx)
│   │   ├── base.go             # Базові компоненти DI (логер, конфіги, спільні модулі)
│   │   ├── cli.go              # Контейнери Uber Fx для консольних команд та воркерів
│   │   └── web.go              # Контейнери Uber Fx для запуску HTTP/REST Web-серверів
│   │
│   ├── cli/                    # КОНСОЛЬНІ КОМАНДИ (Cobra CLI)
│   │   ├── root.go             # Базова команда Cobra
│   │   ├── config.go           # Команда для перевірки/дампу конфігів
│   │   └── web.go              # Команда `server start` для запуску веб-сервера
│   │
│   ├── infrastructure/         # НИЗЬКОРІВНЕВА ІНФРАСТРУКТУРА ТА ДРАЙВЕРИ (Adapters)
│   │   ├── configs/            # Парсинг та типізація конфігурацій (App, JWT, WebServer)
│   │   ├── logger/             # Ініціалізація глобального логера додатка (Zap / Slog)
│   │   ├── cache/              # Драйвери кешування (Redis, In-Memory)
│   │   ├── queue/              # Клієнти черг повідомлень (NATS JetStream, RabbitMQ)
│   │   │
│   │   ├── database/           # Підключення до баз даних (розділені за типами двигунів)
│   │   │   ├── postgres/       # Ініціалізація пулу з'єднань PostgreSQL
│   │   │   ├── clickhouse/     # Налаштування клієнта для аналітичних логів
│   │   │   └── mongodb/        # Налаштування клієнта для документ-орієнтованих даних
│   │   │
│   │   ├── clients/            # Інтеграція із зовнішніми сервісами (Вихідні HTTP/gRPC клієнти)
│   │   │   ├── payment/        # Клієнт платіжного шлюзу (Stripe / PayPal)
│   │   │   └── sms/            # Клієнт сервісу відправки SMS (Twilio тощо)
│   │   │
│   │   ├── pkg/                # Локальні інфраструктурні пакети (утиліти з логікою)
│   │   │   ├── jwt.go          # Технічна логіка JWT (sign, parse, validate)
│   │   │   └── crypto.go       # Хешування паролів та робота з шифруванням
│   │   │
│   │   └── transport/          # Налаштування мережевих протоколів (без бізнес-хендлерів)
│   │       └── http/           # Ініціалізація http.Server + Chi роутера
│   │
│   ├── domains/                # ШАР СУТНОСТЕЙ (Чисті бізнес-моделі та інтерфейси репозиторіїв)
│   │   └── user/               # Опис моделі User + інтерфейс UserRepository
│   │
│   ├── usecases/               # ШАР БІЗНЕС-ЛОГІКИ (Сценарії використання / Application Services)
│   │   └── auth/               # Логіка авторизації (Реєстрація, Вхід, Refresh токени)
│   │
│   ├── web/                    # ВХІДНІ HTTP АДАПТЕРИ (Первинні адаптери / Huma v2)
│   │   ├── api/                # Ендпоінти, розділені за бізнес-контекстом та документацією
│   │   │   ├── admin/          # Обробники та роутер для Панелі Адміністратора
│   │   │   ├── portal/         # Обробники та роутер для Клієнтського Порталу
│   │   │   └── common/         # Спільні обробники (Healthcheck, Version, Auth обробники)
│   │   ├── middleware/         # HTTP Мідлварі (JWT Auth Checker, CORS, Recovery)
│   │   └── web.go              # Точка зборки HTTP адаптера
│   │
│   ├── utils/                  # ДОПОМІЖНІ УТИЛІТИ (Чисті хелпери без стану та залежностей)
│   │    └── files.go           # Робота з файловою системою (читання/запис файлів)
│   └── workers/                # Вхід через фонові потоки (Споживачі подій)
│       ├── nats_consumer/      # Обробники топіків NATS JetStream
│       ├── rabbit_consumer/    # Обробники черг RabbitMQ
│       └── ws_consumer/        # Обробники потокових повідомлень WebSocket
