# 🏗 Архітектура Проєкту: Clean & Hexagonal Architecture + Uber Fx

Цей проєкт побудований на принципах **Чистої (Clean)** та **Гексагональної (Hexagonal / Ports & Adapters)** архітектури з використанням Dependency Injection фреймворку **Uber Fx** та CLI-менеджера **Cobra**.

Головна мета архітектури — повна ізоляція бізнес-логіки системи від зовнішніх факторів: баз даних, черг повідомлень, веб-фреймворків та протоколів зв'язку.

---

## 📂 Фінальна структура папок

```text
.
├── cmd/
│   └── app/
│       └── main.go             # Точка входу. Ініціалізує Cobra CLI команди
│
├── internal/
│   ├── app/                    # БУТСТРАП (Складання додатків за допомогою Uber Fx)
│   │   ├── app.go              # Глобальний монолітний модуль (все в одному)
│   │   ├── api_web.go          # Збірник суто для публічного веб-сервера
│   │   ├── api_admin.go        # Збірник суто для адмін-панелі
│   │   ├── grpc_server.go      # Збірник для gRPC сервера
│   │   └── workers_nats.go     # Збірник для фонових воркерів черги
│   │
│   ├── infrastructure/         # НИЗЬКОРІВНЕВЕ "ЗАЛІЗО" ТА ДРАЙВЕРИ
│   │   ├── db/                 # Драйвери баз (postgres.go, clickhouse.go)
│   │   ├── cache/              # Драйвер кешу (redis.go)
│   │   ├── queue/              # Конект до черг (nats.go, rabbitmq.go)
│   │   └── transport/          # Налаштування мережевих протоколів (без хендлерів!)
│   │       ├── http/           # Ініціалізація http.Server + Chi + Huma
│   │       ├── grpc/           # Налаштування net.Listen + grpc.NewServer()
│   │       ├── websocket/      # Конфіг gorilla/websocket Upgrader
│   │       ├── smtp/           # Клієнт відправки пошти
│   │       └── imap/           # Клієнт для читання пошти (IDLE лісенер)
│   │
│   ├── domains/                # ШАР СУТНОСТЕЙ (Тільки таблиці БД та CRUD)
│   │   ├── user/               # Моделі користувача для Postgres + Репозиторій
│   │   └── analytics/          # Моделі логів для ClickHouse + Репозиторій
│   │
│   ├── usecases/               # ШАР БІЗНЕС-ЛОГІКИ (Сценарії використання / Оркестрація)
│   │   ├── auth/               # Логіка авторизації (admin_login.go, user_login.go)
│   │   └── visit_processor/    # Логіка обробки візитів та аналітики (dto.go, process.go)
│   │
│   # ------------------------------------------------------------------
│   # ВХІДНІ АДАПТЕРИ (Точки входу / Ендпоїнти додатка)
│   # ------------------------------------------------------------------
│   ├── web/                    # Вхід через HTTP REST (Huma PublicAPI / AdminAPI)
│   │   ├── portal/             # Хендлери та роути портала користувача
│   │   ├── admin/              # Хендлери та роути адмінки
│   │   └── public/             # Хендлери та роути публічного сайту
│   │
│   ├── grpc/                   # Вхід через gRPC (Реалізація наших .pb сервісів)
│   │
│   └── workers/                # Вхід через фонові потоки (Споживачі подій)
│       ├── nats_consumer/      # Обробники топіків NATS JetStream
│       ├── rabbit_consumer/    # Обробники черг RabbitMQ
│       └── ws_consumer/        # Обробники потокових повідомлень WebSocket
